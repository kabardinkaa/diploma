# Выбор embedding-модели

## Решение

Для учебного RAG выбран `intfloat/multilingual-e5-base`.

- Основной корпус и запросы пользователей русскоязычные, а E5 поддерживает
  многоязычный semantic retrieval.
- Размерность модели - 768. Для 50 документов это около 150 KiB сырых
  `float32`-векторов без учета индекса и метаданных.
- Модель запускается локально: документы внутренней техподдержки не отправляются
  во внешний API.
- API-инференс стоит $0. Локальный запуск требует загрузки весов, памяти и CPU,
  поэтому первый вызов заметно медленнее последующих.
- E5 явно разделяет короткий запрос и длинный документ префиксами `query:` и
  `passage:`. Это соответствует асимметричному поиску в проекте.

## Оценка для 50 документов

Текущая база содержит 5 документов со средним размером 255 символов текста.
Если 50 документов будут сопоставимого размера, корпус составит примерно
12 750 символов. При грубой учебной оценке 3-4 символа на токен это
3 188-4 250 токенов.

Для локального `multilingual-e5-base` стоимость API-индексации такого корпуса
равна $0. При учебном тарифе OpenAI `text-embedding-3-small` $0.02 за 1 млн
токенов тот же одноразовый прогон стоил бы примерно $0.000064-$0.000085.
Это оценка по тарифу из материалов курса, а не счет провайдера; повторная
индексация без кеша умножает расход на число прогонов.

## Сравнение с OpenAI

`text-embedding-3-small` проще эксплуатировать: не нужно хранить веса модели,
а вычисление выполняет провайдер. Взамен появляются передача внутреннего
корпуса во внешний сервис, зависимость от сети и тарифа, а также необходимость
обрабатывать лимиты API.

Локальный E5 требует больше диска и дает более высокую задержку на CPU, особенно
при первом запуске. Для небольшого конфиденциального русскоязычного корпуса
этот компромисс приемлем. Качество проверяется проектным mini-benchmark, а не
только публичным рейтингом MTEB.

## Результат live smoke-test

Прогон `intfloat/multilingual-e5-base` на пяти парах проекта дал правильный
порядок `relevant > irrelevant` для 5 из 5 запросов. Векторы имеют размерность
768 и L2-норму 1.0. На первой паре score составил 0.876590 для релевантного
документа и 0.787760 для нерелевантного.

Добавление `query:` повысило релевантный score в 4 из 5 пар; максимальный
наблюдаемый прирост составил 0.012249. В одной паре изменение было -0.000987,
поэтому эффект префикса на этой маленькой выборке нельзя считать универсальным.
Префикс всё равно обязателен по контракту E5 и должен проверяться на более
крупном эталонном наборе.

Холодный вызов вместе со скачиванием и загрузкой модели занял 183.7152 с.
Повторный вызов того же текста из disk cache занял 0.0002 с. Эти замеры
относятся к текущей учебной машине и не являются нагрузочным тестом.

## Воспроизводимость

Ключ дискового кеша включает имя модели, тип embedding (`plain`, `query` или
`passage`) и исходный текст. Смена `EMBEDDING_MODEL` автоматически перестает
использовать старые векторы. Для полноценной смены модели будущий векторный
индекс также потребуется построить заново.
